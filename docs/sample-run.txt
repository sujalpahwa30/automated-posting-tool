The demo platform is a local sandbox only, so its public_access is false and its
URL is not reachable from another machine. It is not counted towards the
third-party platform requirement.

5) Invalid input: two CTA links
-------------------------------

POST http://localhost:4000/posting

{
  "message": "Two links https://a.example.com and https://b.example.com"
}

HTTP/1.1 422 Unprocessable Entity
Content-Type: application/json

{
  "detail": "Request validation failed",
  "errors": [
    {
      "field": "message",
      "message": "message must contain exactly one CTA link (found 2)",
      "type": "value_error"
    }
  ]
}

6) Invalid input: no CTA link
-----------------------------

POST http://localhost:4000/posting

{
  "message": "no link here at all"
}

HTTP/1.1 422 Unprocessable Entity

{
  "detail": "Request validation failed",
  "errors": [
    {
      "field": "message",
      "message": "message must contain exactly one CTA link (found 0)",
      "type": "value_error"
    }
  ]
}

Rejected requests never reach the platforms, so no post is created.

Platforms are published concurrently, so a slow or failing provider does not
block the others: each platform returns its own result and the endpoint always
answers with HTTP 200 plus per-platform status details.
